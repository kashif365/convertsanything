1. PROJECT OVERVIEW
================================================================================

Project Name: Convertsanything
Description: A Laravel 12-based web application offering free online file 
             conversion tools for documents, images, and text processing.
             
Brand: Convertsanything (Teal theme: #14b8a6)
Framework: Laravel 12 with Blade templating
Frontend: Vanilla JavaScript + Plain CSS (Poppins font family)
Python Support: Yes (for document processing and image layout extraction)
Database: SQLite (local) or MySQL (production recommended)

Core Services:
- PDF to Word conversion (high-fidelity with PyMuPDF + OCR)
- Word to PDF conversion (LibreOffice headless bridge)
- PDF merge and split operations
- Image format conversions (JPG, PNG, WebP, GIF, BMP, TIFF)
- Image compression and resizing
- Text analysis and case conversion
- Word counting

4. LOCAL DEVELOPMENT SETUP
================================================================================

PREREQUISITES:
  1. Windows 10+ or macOS/Linux
  2. Laragon installed (includes Apache, PHP, MySQL)
  3. Python 3.10+ installed on system path
  4. LibreOffice installed (for Word→PDF conversion)
  5. Git installed

STEP-BY-STEP SETUP:

4.1 CLONE OR EXTRACT PROJECT
    $ cd e:\laragon\www
    $ git clone <repo-url> cnproject
    OR
    $ Extract cnproject folder here

4.2 NAVIGATE TO PROJECT
    $ cd cnproject

4.3 INSTALL PHP DEPENDENCIES
    $ composer install
    (This reads composer.json and installs all packages in vendor/)

4.4 INSTALL PYTHON DEPENDENCIES
    $ python -m pip install -r requirements.txt
    
    requirements.txt contains:
    - pymupdf (fitz) - for PDF layout extraction
    - rapidocr-onnxruntime - for OCR fallback
    - pillow - for image processing
    - numpy - for numerical operations

4.5 COPY ENVIRONMENT FILE
    $ copy .env.example .env
    (or manually create .env with the variables below)

4.6 CONFIGURE .env FILE
    Key variables to set:
    
    APP_NAME=Convertsanything
    APP_ENV=local
    APP_DEBUG=true
    APP_URL=http://localhost:3000  (or your Laragon port)
    
    DATABASE_CONNECTION=sqlite        (or mysql for production)
    DATABASE_URL=sqlite:database.sqlite
    
    CONVERSION_TIMEOUT=180            (seconds for external processes)
    PYTHON_PATH="C:\Python310\python.exe"  (or wherever Python is installed)
    PYTHON_SCRIPTS_DIR="scripts"      (relative path to scripts/)
    
    LIBREOFFICE_PATH="C:\Program Files\LibreOffice\program\soffice.exe"
    LIBREOFFICE_PROFILE_DIR="temp/libreoffice_profile"
    
    CACHE_DRIVER=file
    SESSION_DRIVER=file
    QUEUE_CONNECTION=sync

4.7 GENERATE APP KEY
    $ php artisan key:generate
    (This creates a unique encryption key for sessions)

4.8 CREATE SQLITE DATABASE (if not exists)
    $ touch database/database.sqlite
    (SQLite file-based database for local development)

4.9 CONFIGURE STORAGE DIRECTORIES
    Ensure these directories exist and are writable:
    $ mkdir -p storage/app/public
    $ mkdir -p storage/app/temp
    $ mkdir -p storage/framework/cache
    $ mkdir -p storage/framework/sessions
    $ mkdir -p storage/logs

4.10 START LARAGON
    Open Laragon app → Click "Start All"
    This starts Apache and any configured services

4.11 ACCESS LOCAL APP
    Navigate to: http://localhost:3000 (or your configured Laragon port)
    OR use the domain configured in Laragon (if any)

4.12 OPTIONAL: SETUP VSCODE ENVIRONMENT
    Install extensions:
    - PHP Intelephense (PHP code intellisense)
    - Blade formatter (Blade template formatting)
    - Prettier (JavaScript/CSS formatting)
    - Python extension (for Python script editing)

5.2 REQUEST-RESPONSE FLOW

CLIENT REQUEST FLOW:
1. User selects file in dropzone (HTML file input)
2. JavaScript validates file (type, size, count)
3. User adjusts parameters (quality slider, format, dimensions)
4. User clicks "Convert" button
5. JavaScript shows global loader overlay
6. FormData posted to /api/{tool} endpoint
   - Multipart form with files and parameters
   - CSRF token in header
7. Laravel route routes to appropriate controller
8. Controller validates input:
   - File MIME type
   - File size
   - Required parameters
   - CSRF token
9. If validation fails → return JSON error (422)
10. If validation passes → Call Service method
11. Service processes file (may call Python or external tool)
12. Service stores result in temp directory
13. Service returns JSON with download URL, preview, size info
14. Controller returns JSON response
15. JavaScript renders results:
    - Shows download button
    - Shows file size badges
    - Hides loader overlay
    - Shows success status
16. User clicks Download
17. Browser fetches file from /storage/app/temp/{filename}
18. File downloads with proper headers

ERROR HANDLING:
- If processing fails → Service throws Exception
- Controller catches → returns JSON error
- JavaScript displays error message
- Loader hidden
- User can retry

5.3 FILE FLOW DIAGRAM

UPLOAD → STORE IN TMP → PROCESS → STORE OUTPUT → DOWNLOAD → CLEANUP
  ↓        ↓               ↓          ↓            ↓         ↓
Input   move_uploaded    Service  storage/app/  Serve as   Delete
File    file to tmp/     logic    temp/         download   after
        working          (Python)  {file.ext}    24hrs      24hrs

6.2 CONTROLLER LAYER

Controllers receive HTTP requests and coordinate response.

EXAMPLE: DocumentController@wordToPdf

  public function wordToPdf(Request $request)
  {
    // 1. VALIDATE INPUT
    $request->validate([
      'file' => 'required|file|mimes:doc,docx|max:52428800'
    ]);
    
    // 2. EXTRACT UPLOADED FILE
    $file = $request->file('file');
    $tmpPath = storage_path('app/temp');
    $fileName = uniqid() . '_' . $file->getClientOriginalName();
    $filePath = $tmpPath . '/' . $fileName;
    
    // 3. MOVE FILE TO TEMP
    $file->move($tmpPath, $fileName);
    
    // 4. CALL SERVICE
    try {
      $result = (new DocumentToolService())->wordToPdf($filePath);
    } catch (Exception $e) {
      return response()->json([
        'success' => false,
        'error' => $e->getMessage(),
        'message' => 'Word to PDF conversion failed'
      ], 422);
    }
    
    // 5. RETURN SUCCESS RESPONSE
    return response()->json([
      'success' => true,
      'message' => $result['message'],
      'filename' => $result['filename'],
      'downloadUrl' => $result['downloadUrl']
    ]);
  }

6.3 SERVICE LAYER

Services contain business logic and orchestrate operations.

EXAMPLE FLOW: DocumentToolService->wordToPdf()

  - Detects LibreOffice path from .env
  - Creates isolated user profile for LibreOffice
  - Calls Python bridge script via Symfony Process
  - Monitors subprocess output (JSON status)
  - If success: returns download URL and metadata
  - If failure: throws exception with error details
  - Cleans up temp files (keeps output for download)

8. PYTHON INTEGRATION
================================================================================

8.1 WHERE PYTHON IS USED

1. PDF to Word Conversion
   - Script: scripts/pdf_to_word_layout.py
   - Purpose: Extract text, layout, images from PDF
   - Libraries: PyMuPDF (fitz), RapidOCR, Pillow
   
2. Word to PDF Conversion (Fallback)
   - Script: scripts/word_to_pdf_libreoffice.py
   - Purpose: Bridge to LibreOffice headless conversion
   - Use when: Direct LibreOffice call via PHP has issues

8.2 PYTHON SUBPROCESS EXECUTION

Laravel calls Python via Symfony Process:

  use Symfony\Component\Process\Process;
  
  // Create process
  $process = new Process([
    'python',
    'scripts/pdf_to_word_layout.py',
    '/path/to/input.pdf',
    '/path/to/output.docx'
  ]);
  
  // Set working directory
  $process->setWorkingDirectory(base_path());
  
  // Inherit environment (critical for Python path)
  $process->inheritEnvironmentVariables();
  $process->setEnv(['PYTHONHASHSEED' => '0'] + $_ENV);
  
  // Set timeout
  $process->setTimeout(180);
  
  // Wait for completion
  $process->mustRun();
  
  // Get output
  $output = $process->getOutput();

8.3 PYTHON SCRIPT DETAILS

PDF TO WORD LAYOUT EXTRACTION:
  Input: /path/to/input.pdf
  Output: /path/to/output.json (or directly to DOCX via PHPWord)
  
  Process:
  1. Open PDF with PyMuPDF
  2. For each page:
     a. Extract text spans (with positions, font, size)
     b. Extract images
     c. Detect alignment and spacing
     d. Group lines into paragraphs
  3. If extraction fails: fall back to RapidOCR
  4. Output JSON with structured data
  5. Laravel reads JSON and generates DOCX via PHPWord

WORD TO PDF LIBREOFFICE BRIDGE:
  Input: /path/to/input.docx
  Output: /path/to/output.pdf
  
  Process:
  1. Detect soffice.exe location
  2. Create isolated LibreOffice user profile
  3. Launch headless: soffice --headless --convert-to pdf input.docx
  4. Monitor process output
  5. Parse result JSON for success/errors
  6. Return output PDF path

8.4 PYTHON DEPENDENCIES (requirements.txt)

  pymupdf>=1.23.0              # PDF extraction (fitz)
  rapidocr-onnxruntime>=1.3.0  # OCR for scanned PDFs
  pillow>=10.0.0               # Image processing

INSTALLATION:

9. IMAGE TOOLS ARCHITECTURE
================================================================================

9.1 IMAGE TOOL ENDPOINTS AND FLOW

All image tools follow a consistent pattern:

ENDPOINT STRUCTURE:
  POST /api/images/{tool}
  
  - jpg-to-png:   Convert JPEG to PNG (lossless)
  - png-to-webp:  Convert PNG to WebP (lossy, smaller)
  - compress:     Reduce file size (quality slider + format choice)
  - resize:       Scale to dimensions (width, height, aspect lock)
  - convert:      Convert any image to any format (universal)

9.2 IMAGE PROCESSING SERVICE

File: app/Services/ImageToolService.php

Key Methods:
  - jpgToPng(array $files): array
  - pngToWebp(array $files, int $quality): array
  - compress(array $files, int $quality, string $format): array
  - resize(array $files, int $width, int $height, bool $lockAspect): array
  - convertAny(array $files, string $format, int $quality): array

PROCESSING FLOW:
  1. Receive uploaded file(s)
  2. Read image via Intervention Image (createImageBitmap)
  3. Apply transformations:
     - Format conversion (encodeByFormat)
     - Quality adjustment (toWebp($quality))
     - Resizing (scale() via Intervention)
  4. Encode to target format:
     - PNG: lossless (toPng())
     - WebP: lossy with quality (toWebp($quality))
     - JPEG: lossy with quality (toJpeg($quality))
  5. Store output in temp directory
  6. Calculate file sizes (input → output)
  7. Return JSON with:
     - filename
     - downloadUrl
     - previewUrl (for images)
     - sizeLabel (e.g., "2.6 MB → 132.8 KB")
     - fallback (PNG backup for lossy formats)

9.3 INTERVENTION IMAGE LIBRARY

Used for all image manipulations:
  - Read images: $image = Image::read($path)
  - Transform: $image->scale(width, height)
  - Encode: $encoded = $image->toPng() / toWebp($q) / toJpeg($q)
  - Save: file_put_contents($path, $encoded->toString())

9.4 IMAGE TOOL UI FLOW (Frontend)

1. User uploads images via dropzone
2. JavaScript shows estimated output size (based on quality slider)
3. User adjusts quality/format/dimensions
4. Estimate updates in real-time using browser canvas encoding

    - Preview thumbnail (if available)

9.5 SUPPORTED IMAGE FORMATS

10.3 WORD TO PDF CONVERSION FLOW

File: app/Services/DocumentToolService->wordToPdf()

ARCHITECTURE:
  Direct Method (if LibreOffice available):
    1. Laravel detects soffice.exe path from .env
    2. Creates isolated LibreOffice user profile
    3. Calls Python bridge script:
       $ python scripts/word_to_pdf_libreoffice.py \
         --input input.docx \
         --output output.pdf \
         --soffice C:\Program Files\LibreOffice\program\soffice.exe
    4. Python process:
       - Detects soffice location
       - Creates user profile: temp/libreoffice_profile
       - Launches headless: soffice --headless \
         --user-installation-dir=$(profile_dir) \
         --convert-to pdf input.docx
       - Emits JSON status updates
       - Returns exit code (0 = success)
    5. Laravel receives output PDF
    6. Stores in temp directory
    7. Returns download URL

KEY POINTS:
  - LibreOffice headless mode is used (no GUI)
  - Requires isolated user profile (avoids lock conflicts)
  - Timeout: 180 seconds (configurable in .env)

10.4 PDF MERGE FLOW

PROCESS:

TECHNOLOGY:

  {
    // Validate filename (only alphanumeric + underscores)
    if (!preg_match('/^[a-zA-Z0-9_\-.]+$/', $filename)) {
      abort(404);
    }
    
    $path = storage_path("app/temp/$filename");

    if (!file_exists($path)) {
      abort(404);
    }
    
    // Serve file with download headers
    return response()->download($path);

     $ where python         (Windows)
  2. Update .env: PYTHON_PATH="/usr/bin/python3"

Cause: soffice.exe path incorrect
Solution:
  1. Find LibreOffice:
     $ which soffice        (Linux)
     $ where soffice.exe    (Windows)
  2. Update .env with correct path
  3. Verify: soffice --version

Cause: File too large or server slow
Solution:
  1. Increase timeout in .env: CONVERSION_TIMEOUT=300 (5 minutes)
  2. Optimize file size (compress uploads)
  3. Check server resources (CPU, RAM, disk space)

ISSUE 4: Permission denied errors

Cause: Directory permissions wrong
Solution:
  $ chmod -R 775 storage/
  $ chmod -R 775 bootstrap/cache/

ISSUE 5: Out of disk space

Cause: Temp files not cleaning up
Solution:
  1. Manual cleanup: rm -rf storage/app/temp/*
  2. Check available space: df -h
  3. Consider external storage (S3, etc.)

ISSUE 6: Image quality loss

Cause: JPEG/WebP quality too low
Solution:
  1. Adjust quality slider in UI (default 85%)
  2. Use PNG for lossless (larger file)
